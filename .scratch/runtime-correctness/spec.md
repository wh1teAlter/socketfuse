# SocketFuse 统一运行时与连接协议

**Status:** ready-for-agent

## Problem Statement

多标签页共享 socket 后，应用的收到确认、心跳和恢复指令必须按物理连接处理；页面业务回调按标签页执行。当前两套接入实现还存在队列无法排空、旧参与期复用、异步协议跨尝试污染、重试预算漂移及资源计费不足，使共享连接的公开保证无法稳定兑现。

## Solution

使用一个连接运行时服务 Worker 端口和页面 MessageChannel；以参与期、连接 epoch、物理尝试、重连计划分别定义所有权。应用在自定义 Worker 的同步连接扩展中返回收到确认、业务投影和重连意图。自动和显式恢复共用预算，显式请求可选择不计数，但不重置已用次数。页面仅接收业务投影并管理本地回调。

## User Stories

1. 作为多标签页应用开发者，我希望相同共享配置复用唯一 socket，使增加标签页不会增加物理连接。
2. 作为应用开发者，我希望冲突配置明确失败，使不同协议和预算不会被静默混用。
3. 作为协议开发者，我希望在 Worker 内对每个物理通知回复一次收到确认，使回复次数不随标签页增加。
4. 作为协议开发者，我希望控制消息可消费或投影，使页面只接收业务需要的数据。
5. 作为协议开发者，我希望连接期状态可参与心跳生成，使多页共用一个心跳时钟。
6. 作为协议开发者，我希望回复只属于当前尝试，使过期确认不会在新 socket 上发送。
7. 作为应用开发者，我希望三次重连预算覆盖自动恢复和主动恢复，使协议指令不会隐式刷新额度。
8. 作为应用开发者，我希望主动恢复可明确不计数，使正常 endpoint 轮换不必消耗错误恢复预算。
9. 作为应用开发者，我希望不计数恢复不补充额度，使失败后的自动重连仍遵守原预算。
10. 作为应用开发者，我希望并发重连合并且拒绝冲突，使多页请求不会连续拆掉新连接。
11. 作为应用开发者，我希望预算不足先拒绝，使健康连接不被无效请求断开。
12. 作为应用开发者，我希望稳定连接才重置预算，也能关闭稳定重置，使预算周期符合业务需要。
13. 作为页面开发者，我希望 close 后可重新 open，使页面参与与 client 实例生命周期分离。
14. 作为页面开发者，我希望取消 open 只取消自己的等待，使并发使用者和连接需求不受影响。
15. 作为页面开发者，我希望恢复失败保留已选 transport，使网络故障不会偷偷增加 direct socket。
16. 作为页面开发者，我希望 raw 的 Blob 表示只在本地转换，使不同页面可共享相同 wire 连接。
17. 作为业务开发者，我希望每帧每个分派 key 至多选一个参与者，使页面副作用有清楚的接收范围。
18. 作为业务开发者，我希望过期资格与回放不能启动 keyed handler，使交接不会补执行旧帧。
19. 作为业务开发者，我希望收到、入队和送达的含义明确，使我不会把本地回执当作业务成功。
20. 作为应用开发者，我希望已入队业务消息维持 FIFO 且最终被唤醒，使背压恢复后无需新建连接。
21. 作为应用开发者，我希望发送快照不被外部修改，使排队内容等于接纳时内容。
22. 作为应用开发者，我希望 pending、clone、wire、delivery 与 replay 分别有界，使慢页面和大缓冲视图不会无限占用资源。
23. 作为页面开发者，我希望暂停时不更新 data，回放时逐条更新，使 handler 看到一致的最新派发值。
24. 作为应用开发者，我希望错误、日志与诊断不含凭据或内部文本，使自定义协议异常不会泄露秘密。
25. 作为应用开发者，我希望 logger 或回调失败不阻止其他消费者，使观察逻辑不影响连接推进。
26. 作为协议开发者，我希望无效异步协议返回明确终止，使永不 settle 的转换不能堵塞连接。
27. 作为协议开发者，我希望异步准备有期限、取消和未结算上限，使旧凭据请求无法覆盖新计划或无限累积。
28. 作为库维护者，我希望发布验收从无 dist 环境独立运行且发布已验证的 tarball，使 CI 和实际 npm 产物一致。
29. 作为使用者，我希望公开类型、中文 TSDoc、指南和示例描述最终行为，使破坏性升级有明确迁移路径。

## Implementation Decisions

- 沿用已批准的统一 runtime、同步协议、单接收者分派及 Worker 协议动作四项 ADR。底层连接不依赖页面或 Worker。
- 端口握手只协商版本与资源能力；成功后永久锁定 transport，attach 才创建连接需求。custom Worker 禁止 direct fallback。
- 同一 client 每次参与使用新 session；同一连接条目使用 epoch；每次实际调用 socket 工厂递增 attempt；计划身份覆盖准备直至新尝试结束建连。
- 旧 socket 未确认关闭前保留条目，后续需求只记录；禁止通过人为超时删除条目来并行创建第二 socket。
- 所有协议转换同步；唯一异步扩展是有界准备。无效 thenable 产生终止性协议契约错误，应用 throw 按阶段安全映射。
- onFrame 的全部结果先校验，再依次尝试回复、业务投影和重连；效果不能网络回滚，每步核验 attempt。
- 重连计数在 socket 工厂调用前提交；计数计划先预留；取消未启动计划释放；重复请求加入，冲突策略拒绝。
- 原生正常 close 默认不自动恢复，但允许显式恢复；真正 fatal/协议契约错误使条目终止，须完整回收后新建。
- 分派 stamp 包含参与期、epoch 和 grant 代际；lease 确认从本地发送时刻计时。保证是每帧单接收者选择，不是异步副作用互斥。
- 字节预算区分克隆表示与 wire；预检查、克隆及接收端校验共同约束合作调用方。浏览器无法在执行 Proxy trap 前普遍识别 Proxy，文档不承诺副作用为零的 Proxy 检测。
- 一套有界业务 FIFO、一个 drain timer、一套 runtime replay；控制回复可穿插但不排队跨尝试。
- 所有 Promise API 用 rejection 失败；发送成功 post 后回复丢失使用结果未知错误，不自动重发。
- 发布包验收只构建和打包一次，解包验收与最终发布指向同一文件；权限、版本 PR 与 OIDC 门禁保持。

## Testing Decisions

- 主验收边界为页面公开 client → 原生端口 → 运行时 → 可控 socket 工厂，shared/direct 运行相同契约用例。只断言公开事件、收到的 wire、状态、预算和可观察资源释放。
- 延续现有可控 socket 与 timer 测试方式，专门构造旧 socket 事件、迟到端口消息、预留取消、背压变化和准备超期；必要时在连接边界补精确时序测试。
- 三浏览器多页验证一帧一次自定义 Ack、唯一心跳、暂停回放不重跑协议、key 交接、close/idle/reopen 和 Worker 恢复。
- 发布验收增加无 dist 的隔离场景，验证包入口、类型、SSR、安全文件与实际 tarball。
- 最终 lint → typecheck → test → build → docs:check → release:verify → test:e2e → diff 检查严格串行。测试成功仅证明断言行为；单 socket 与不等待页面等不变量另以所有权/调用路径审查核验。

## Out of Scope

框架绑定、RPC、通用 Ack/关联服务、topic、内置业务去重、可靠送达、强制取消用户 Promise、跨 Worker 持久化预算、跨库副本全局注册表、新运行时依赖、发布 npm 或向外部 tracker 发消息。

## Further Notes

用户已授权此方案的常规细化与实施，只有产品取舍或实质方案偏离再沟通。任务拆分使用仓库既有本地 tracker。改动是一次集成的破坏性重构，中间类型迁移不单独发布；最终删除旧路径与临时兼容。
