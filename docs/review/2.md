# 全仓审查结论

发现 **1 个 P0、11 个 P1、9 个 P2**。存在跨 tab 敏感信息泄露、Worker 资源耗尽、共享连接状态机失效及 SSR 误降级等阻塞问题。

|---|---|
| `pnpm install --frozen-lockfile` | 通过 |
| `pnpm check` | 通过：lint、类型、32 个 Vitest、构建、TypeDoc、publint、release verify |
| `pnpm test:e2e` | 通过：Chromium / Firefox / WebKit，9/9 |

## 架构摘要

```text
PageWebSocketClient
  ├─ SharedWorkerTransport ─ MessagePort ─ SharedWorker runtime
  │                                      └─ id pool
  │                                          └─ ConnectionController
  │                                              └─ native WebSocket
  └─ DirectTransport ─ realm-local pool ────── ConnectionController
                                                 └─ native WebSocket

wws public package bundles @wws/core
docs (VitePress /playground) imports public `wws`
@wws/test owns Playwright, ws server, and tarball-consumer verification
CI: frozen install → check → browser E2E
```

## Sub-agent 审查摘要

- runtime / architecture：确认端口与连接池回收、入站 fan-out、握手、revision、reconnect、BFCache/Worker restart、autoClose 存在多项 P1 违约。
- API / security：确认一个 P0 跨 tab 错误信息泄露；Worker 控制协议可被同源脚本伪造并绕过资源限制；Node SSR 会错误创建 direct client。
- quality / delivery：确认 E2E 存在并发隔离缺陷且覆盖面不足；tarball 门禁未验证 Vite/Worker 消费；文档和 sourcemap 存在交付问题。

## Findings

### P0 — Worker 将未脱敏的 adapter/服务端错误广播到同 id 的其他页面

- **文件与行号**：`packages/core/src/worker-runtime.ts:141-144,221-225`；`packages/core/src/connection-controller.ts:509-513`；`packages/core/src/shared-worker-transport.ts:60-62`；`packages/core/src/page-client.ts:45-50`
- **证据与触发条件**：`serializeError()` 原样传递 `WwsError.message`，controller 向所有 sink 广播错误，页面只过滤 `details`，仍保留 message。自定义 adapter `decode()` 抛出含 `super-secret` 的错误时，另一同 id client 的 `onError` 可收到该秘密。
- **实际影响**：服务端 payload、token、完整 URL 或 adapter 异常文本可跨 tab 泄露。
- **与规格的关系**：违反 v1 §19 的 Worker 错误脱敏要求及 §21“adapter error/服务端 payload 不得直接暴露”。
- **修复方向**：Worker 边界只传递 code、retryable、fatal 与白名单安全字段；按错误码生成固定公开 message。
- **应补充的测试**：integration：两个同 id client，分别注入 token、URL、服务端 payload，断言 EventTarget、onError、logger 都不泄露原文。

### P1 — 控制协议仅浅校验，任意同源 port 可污染共享配置并绕过包大小限制

- **文件与行号**：`packages/core/src/control.ts:53-76`；`packages/core/src/worker-runtime.ts:68-83,247-291,379-397`
- **证据与触发条件**：`hello.shared`、`restore`、数值范围及 canonical/fingerprint 一致性均未校验；`Map` 的 `JSON.stringify()` 为 `{}`，3 MiB Map payload 可绕过 2 MiB control envelope 限制并成功 attach。伪造 `shared.reconnect = false` 可让正常同 id client 在断线后不重连。
- **实际影响**：同源脚本可改变共享连接行为、放宽资源上限，破坏多 tab 隔离与资源治理。
- **与规格的关系**：违反 v1 §9.2、§21.1 的运行时控制消息验证、同源威胁模型及资源上限要求。
- **修复方向**：Worker 侧白名单深度解析并重新规范化 shared/restore；重算 canonical/fingerprint；准确计量 structured-clone 数据。
- **应补充的测试**：unit + integration：Map/Set/ArrayBuffer 超限、负数/NaN、伪造 fingerprint、未知字段及伪造 reconnect 配置。

### P1 — Node/SSR 环境错误创建 direct client

- **文件与行号**：`packages/wws/src/index.ts:47-54,81-116`
- **证据与触发条件**：Node 22 有 `WebSocket`、无 `SharedWorker`；`createWebSocket(..., { immediate: false })` 返回 direct client，而非抛出 `ENVIRONMENT_UNSUPPORTED`；默认 immediate 还会尝试连接。
- **实际影响**：SSR/Node 进程可能意外建立 WebSocket。
- **与规格的关系**：违反 v1 §3.3：非浏览器可 import，但实际创建/连接必须报 `ENVIRONMENT_UNSUPPORTED`。
- **修复方向**：在创建 client 前识别浏览器 page 环境，不能把 Node WebSocket 视作 direct fallback 能力。
- **应补充的测试**：package-consumer test：Node ESM 三入口 import 成功，但两种 immediate 配置均不能发起连接且创建报环境错误。

### P1 — 未完成 hello 的端口永不回收，可永久耗尽 Worker 端口配额

- **文件与行号**：`packages/core/src/worker-runtime.ts:162-176,369-410`
- **证据与触发条件**：未 attach port 的超时回调调用 `detach(port, true)`，但 `clients.get(port) === undefined` 时直接 return，不会删除 `connectedPorts`、清 timer 或 close port。
- **实际影响**：256 个不发送 hello 的端口后，后续健康 client 永久无法接入 Worker。
- **与规格的关系**：违反 v1 §21.1：未 attach port 必须在超时后清理且不得影响健康 client。
- **修复方向**：将端口关闭/计时器清理与已 attach client 的 controller detach 解耦。
- **应补充的测试**：fake clock 下耗尽端口、推进 unattached timeout，再验证端口关闭且健康 client 可接入。

### P1 — 空闲 connection controller 永久保留在 Worker pool

- **文件与行号**：`packages/core/src/worker-runtime.ts:253-266`；`packages/core/src/connection-controller.ts:227-232,631-639`
- **证据与触发条件**：runtime 只新增 `connections` entry，除 runtime dispose 外从不删除；最后 client 离开后 controller 仅关闭 socket。
- **实际影响**：历史 id 的 controller、配置、revision 状态持续累积；同 id 在空闲回收后仍可能被旧静态配置永久阻塞。
- **与规格的关系**：违反 v1 §10.2、§22 的资源回收要求。
- **修复方向**：idle close 完成后删除无 demand entry，并隔离旧 timer 与新同 id entry。
- **应补充的测试**：最后 client 离开并越过 idle grace 后，验证 pool entry 被释放和新配置可建立新连接。

### P1 — Worker→page fan-out 无 credit 上限，且 overflow 事件被页面端忽略

- **文件与行号**：`packages/core/src/worker-runtime.ts:225-237`；`packages/core/src/control.ts:25-51`；`packages/core/src/shared-worker-transport.ts:348-357`
- **证据与触发条件**：未 suspended client 的每一帧都直接 `postMessage`；控制协议无 receipt/credit，transport 不处理合法 `overflow` 消息。
- **实际影响**：慢页面可能使 MessagePort 队列无限积压并耗尽内存；应用收不到入站/replay overflow 信号。
- **与规格的关系**：违反 v1 §14 的每 client 256 条 / 4 MiB 上限与 overflow 通知要求。
- **修复方向**：加入 page-runtime receipt/credit，超额丢弃并向 Page client 转换为 `overflow` event。
- **应补充的测试**：integration：慢 client 超过条数和字节上限不增长队列；健康 client 不受影响；overflow 可观察。

### P1 — adapter-frame 握手没有超时，`fatal` frame 被静默忽略

- **文件与行号**：`packages/core/src/connection-controller.ts:420-430,474-507`
- **证据与触发条件**：socket open 即清除 connect timer，进入 `handshaking` 后不设 timer；合法 `fatal` frame 落入默认 return。
- **实际影响**：`open()` 可永久 pending，鉴权/协议 fatal 不会终止连接。
- **与规格的关系**：违反 v1 §8.4 的 fatal 语义和 §11.2 的有限握手超时。
- **修复方向**：增加 handshake deadline；fatal 转换为终态错误并关闭，再按策略决定重连。
- **应补充的测试**：unit：无 ready、fatal frame、timer 清理和 waiter rejection。

### P1 — connecting/handshaking 中更新 URL 不会替换旧 endpoint

- **文件与行号**：`packages/core/src/connection-controller.ts:328-342`
- **证据与触发条件**：`updateUrl()` 仅 state 为 `open` 时 reconnect；旧 socket 已创建但未 ready 时，revision 返回 applied，旧 URL 仍会完成连接。
- **实际影响**：调用方认为 endpoint 已更新，实际仍连到旧服务端。
- **与规格的关系**：违反 v1 §12.2：URL 更新必须关闭旧连接并建立新连接。
- **修复方向**：所有已应用 URL revision 都应取消旧 attempt 并创建新 attempt，防止迟到事件覆盖新状态。
- **应补充的测试**：旧 URL connecting 与 handshaking 时更新 URL，断言旧 socket close、新 factory 使用新 URL。

### P1 — 无 `ready` 的 JSON auth 配置不会发送首帧认证

- **文件与行号**：`packages/core/src/protocol.ts:189-247`；`packages/core/src/connection-controller.ts:420-450`
- **证据与触发条件**：JSON adapter 无 `ready` 时为 `socket-open`；`sendAuth()` 仅在 `adapter-frame` 分支调用。
- **实际影响**：合法的 JSON auth-only 协议会匿名连接或被服务端拒绝。
- **与规格的关系**：违反 v1 §8.5、§12 的 JSON auth 与 revisioned auth 契约。
- **修复方向**：socket open 后按已登记 auth 发送首帧，并定义与 ready 握手的顺序。
- **应补充的测试**：unit：`protocol: { type: 'json', auth: ... }`、immediate false、先更新 auth 后 open，断言首帧认证内容。

### P1 — reconnect backoff 期间调用显式 `reconnect()` 会触发非法状态转换

- **文件与行号**：`packages/core/src/connection-controller.ts:345-360,452-455`；`packages/core/src/connection-state.ts:4-13`
- **证据与触发条件**：state 为 `reconnecting`、socket 为 null 时，显式 reconnect 直接 startSocket；socket open 后尝试 `reconnecting → open`，状态表禁止该转换。
- **实际影响**：断线恢复窗口内的显式重连抛 `INTERNAL_STATE_ERROR`，连接无法恢复。
- **与规格的关系**：违反 v1 §7.2、§10.1 的 reconnect 状态机。
- **修复方向**：取消 backoff 后先过渡到 `connecting`，显式与 timer retry 共用同一 attempt 路径。
- **应补充的测试**：fake timer：close 进入 backoff、立即 reconnect、打开新 socket，断言 open 且无 internal-state error。

### P1 — Worker restart/BFCache 恢复没有 probe、transport 重建或 revision replay

- **文件与行号**：`packages/core/src/page-client.ts:365-396`；`packages/core/src/shared-worker-transport.ts:366-391`
- **证据与触发条件**：pageshow/restore 仅发 `restore`，没有 probe、重建 Worker/port 或重放 URL/auth revision。
- **实际影响**：Worker 重启后的页面保留失效 transport，需应用手动重建 client，Worker 丢失的 endpoint/auth 状态无法恢复。
- **与规格的关系**：违反 v1 §10.4、AC-007。
- **修复方向**：实现 probe timeout、instance-id 变更检测、transport 重建和 revision journal replay。
- **应补充的测试**：integration + E2E：模拟 port/Worker 失效后 pageshow，验证新 hello/attach 及最新 URL/auth 重放。

### P1 — 默认 `autoClose: true` 从未在 pagehide 卸载当前 client

- **文件与行号**：`packages/core/src/config.ts:308-315`；`packages/core/src/page-client.ts:122-136,365-396`
- **证据与触发条件**：配置被保存但未消费；仅 lifecycle.restore 会安装 pagehide handler，且该 handler只 suspend。
- **实际影响**：最后页面退出后通常等待 60 秒 lease timeout，而不是 5 秒 idle grace 才清理连接。
- **与规格的关系**：违反 v1 §7.1、§10.3 的 autoClose/pagehide detach 要求。
- **修复方向**：独立安装 auto-close 生命周期处理，best-effort detach 当前 client，不关闭其他 tab。
- **应补充的测试**：E2E：关闭最后 tab 后在 idle grace 边界关闭；`autoClose: false` 不发送 detach。

### P2 — direct fallback 在 suspended 且不 replay 时仍向冻结页面派发消息

- **文件与行号**：`packages/core/src/page-client.ts:290-301`；对照 `packages/core/src/worker-runtime.ts:225-236`
- **证据与触发条件**：direct + `lifecycle.restore: true` 时，只有 replay 为 true 才抑制分发；SharedWorker 分支会正确丢弃。
- **实际影响**：两个 transport 在相同公开配置下出现不同生命周期语义。
- **与规格的关系**：违反 v1 §3.2、§10.4 的 direct/shared 一致性。
- **修复方向**：suspended 时一律停止派发；仅 replay 开启时写入本地回放缓冲。
- **应补充的测试**：shared/direct contract test，验证 replay false 时均不调用 handler。

### P2 — 非法 Worker 控制响应会静默降级为 direct

- **文件与行号**：`packages/core/src/shared-worker-transport.ts:37-52,291-293,379-391`
- **证据与触发条件**：`INVALID_CONTROL_MESSAGE` 在 fallback allowlist；伪造 welcome 缺少 `workerInstanceId` 后会激活 direct。
- **实际影响**：控制协议损坏时共享语义被静默改为每页直连。
- **与规格的关系**：违反 v1 §18.2、§18.3。
- **修复方向**：从 allowlist 移除 `INVALID_CONTROL_MESSAGE`。
- **应补充的测试**：fake Worker 返回 malformed response，断言不创建 direct socket。

### P2 — `message` EventTarget 先于 `onMessage` 执行

- **文件与行号**：`packages/core/src/page-client.ts:303-313`
- **证据与触发条件**：`dispatchEvent(event)` 在 handler loop 之前。
- **实际影响**：依赖 `onMessage` 先更新派生状态的 EventTarget consumer 观察到反序。
- **与规格的关系**：不符合 v1 §16 的 `data → onMessage handlers → message event` 分发顺序。
- **修复方向**：先执行 handler 快照，再 dispatch EventTarget event，并保持单 handler 异常隔离。
- **应补充的测试**：unit：同时注册两类 listener，断言调用顺序和异常隔离。

### P2 — 声明式 JSON protocol 没有正确推断 JSON 输入输出类型

## 已核实，不是问题

- `ws` 与 `@types/ws` 仅由 `@wws/test` 直接拥有；Playwright 从 test workspace 调用。
- Playground 位于 VitePress `/playground`，没有独立 playground package。
- catalog 仅包含被多个 workspace 直接使用的 TypeScript、tsdown；`vue-eslint-parser` 是根 Flat Config 的合理依赖。
- 未恢复禁止依赖；lockfile 中的相关文本只是上游元数据。
- 没有公开 `subscribe`、`request`、Ack/RPC API；transport 内部 `request()` 是控制协议实现。
- 同 id 的活动连接配置冲突能被拒绝；已成功 Worker 握手后的 socket/heartbeat 故障不会自动切 direct。
- SharedWorker 的 suspend/replay 状态按 port 保存，冻结一个 tab 不会阻塞其他 tab 的消息派发。
- ESM 三入口的模块求值可安全 import；SSR 问题只发生在实际创建 client。

## 测试与验证缺口

- **unit + integration**：控制协议深度验证、structured-clone 大对象计量、错误脱敏、端口/连接池回收。
- **unit**：握手 timeout/fatal、URL revision race、backoff reconnect、JSON auth 首帧。
- **integration**：SharedWorker 与 direct 完整 lifecycle contract、Worker restart/revision replay、入站 credit/overflow。
- **E2E**：隔离的 2/3/20 tab、page close/refresh/BFCache、网络/Worker restart、二进制、普通 socket 不降级。
- **package-consumer**：真实 tgz 的 NodeNext/Bundler、Vite build、三入口 runtime import、inline/custom Worker、SSR create guard。
