- `connection` 未发现对 runtime、page 或 worker 的运行时依赖；Worker 业务回调没有被 runtime await。
- 公开 API 变更带有 `.changeset/unified-protocol-runtime.md`；模块 README 已同步 runtime、transport、page、Worker 和协议职责。
- 旧 `filterInbound`、异步协议队列和 `execution key` 仅出现在历史 ADR、历史 changeset 或迁移规格中；当前实现和现行指南使用 `onFrame`、同步 adapter 与 `dispatchKey`。
- 发布 workflow 继续使用受保护 job、OIDC 和已验收 tarball；工作树没有本地发布动作。

未发现新的 P0–P2 规范问题。生成的 `source.generated.ts` 是 inline Worker 构建产物，属于预期的生成边界。

## Spec

已核验的目标行为包括：统一 shared/direct runtime、永久 transport 选择、参与期重建、单物理 socket、Worker 每帧一次协议处理、统一重连预算、dispatch stamp、FIFO 与资源上限、错误脱敏、无 dist tarball 验收，以及 SSR 入口类型检查。

当前 E2E 由 15 个规格组成，在 Chromium、Firefox、WebKit 共 45 个用例全部通过；新增用例覆盖 Worker Ack 投影、Worker/断线混合重连预算和 Worker 终止后的 BFCache 恢复。

本轮没有确认新的规格缺陷。`acceptPong` 与统一 `maxFrameBytes` 是后续可单独决策的扩展，既有规格和当前实现仍采用已发布的 pong 分类及 `maxEncodedMessageBytes` 契约，因此未在本轮擅自扩大 API。
