# 连接作用域业务扩展在 Worker 内运行一次

需要所有标签页共同生效的入站过滤与重连准备，现在由应用在自己的 SharedWorker 文件中以「连接作用域业务扩展」提供，由 Worker 按共享连接执行一次，而不是让每个页面各自执行再想办法收敛。协议适配器保持无状态、只描述 wire format；跨帧的业务状态（去重表、服务端时钟）属于扩展，不属于适配器。这样一个接口只承担一种生命周期，避免适配器同时充当格式规则与业务状态机。

## Considered Options

- **放宽适配器为有状态处理器**：把去重与时钟塞进 `classify`。代码上可行（适配器实例本就跨重连存活），但会让 `sharedConfig` 参与 fingerprint 的语义失效——有状态对象没有稳定 canonical 表示——并让同一接口承担编解码规则与连接期业务状态两种生命周期。
- **继续只用 execution key**：key 解决的是「哪个页面执行副作用」，与「哪些帧值得派发」是不同问题。入站过滤若用 key 表达，帧仍会广播到全部页面并消耗每页投递额度。
- **库内置去重**：ADR 0002 已把凭据、游标、幂等划归应用；内置去重会把应用协议状态重新搬回库内。

## Consequences

- 入站过滤在 fan-out 之前发生，被丢弃的帧不经过 `MessagePort`，也不消耗任何页面的投递额度；这是它相对 execution key 的实质收益。
- execution key 保留，职责收窄为「必须在页面 realm 完成的副作用」（通知、存储、路由）。Worker 内没有 DOM，这类需求无法由扩展替代。
- 扩展要求自定义 Worker 部署，因此与内联 Worker 的零配置路径互斥；页面声明式 JSON 配置仍是默认路径，不被取代。
- 浏览器可以整体回收 SharedWorker，扩展持有的状态随之丢失。库提供连接生命周期回调作为重建时机，但不持久化状态，也不承诺服务端 exactly-once。
- 每帧扩展必须同步且快速：Worker 是所有标签页共享的单线程，`await` 会直接放大为全局延迟，违反「Worker 不等待页面」不变量。
