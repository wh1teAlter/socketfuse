# 连接扩展处理协议动作，所有重连入口共用预算

应用希望在共享 socket 收到消息时，自定义回复“已收到”、消费控制指令或触发重连。页面 handler 按参与者执行，无法自然保证这类连接协议只处理一次；现有连接扩展的 filterInbound 又只能选择派发或丢弃。把连接协议放进 dispatchKey 页面 handler 会使其依赖页面调度与接收者变更。

保留应用拥有协议状态的边界，将 filterInbound 替换为连接作用域、同步执行的 onFrame。扩展返回有界的回复、业务投影与重连请求，由 runtime 校验并交给 controller 执行。没有通用中间件链或跨帧 Promise 队列，不向扩展暴露原始 socket。自定义 Ack 由应用定义，不改变 sendMessage 只代表本地接纳的契约。心跳仍由一个连接引擎调度；需要连接期状态的生成器可由扩展提供，不能与 adapter 生成器同时执行。

重连的触发来源与是否消耗预算分别建模。所有入口归属同一连接控制器，默认计数；Worker 和页面可以显式请求一次不计数重连。已用次数只在实际启动计数尝试时增加，不因显式请求或豁免恢复。同一计划合并请求并固定计数方式；健康连接被替代前必须先接纳预算，过期请求不能再次替代新连接。预算在连续稳定 open 或新连接条目时重置，稳定重置可以关闭。

这一决策扩展 ADR 0004 的连接业务能力与 ADR 0005 的计划元数据，保持 ADR 0002 的应用协议所有权、ADR 0001 的连接拥有方计划权威，以及同步协议转换原则。它替换重设计初稿中“显式 reconnect 清空预算”的规则，不修改已接受 ADR 对历史实现的记录。

代价是 filterInbound、重连配置、控制协议与部分类型的破坏性迁移。收益是多页不重复处理连接协议，且主动恢复不会隐式绕过次数上限。允许显式不计数意味着预算不约束这类豁免尝试的总量；Worker 收到确认也不承诺页面业务完成或服务端已收到回复。

API、生命周期、错误顺序、预算竞争与回归场景见[完整规格](../specs/worker-protocol-and-reconnect-budget.md)。
